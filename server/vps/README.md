# Картинки, выбранные пользователем

VPS принимает `POST /upload`: обложки плеера, хранение 1 час после последней
загрузки. `POST /upload?kind=own`: картинки, выбранные вручную для своего
статуса, треков без обложки или всех треков, хранение 6 часов.

Адрес: `https://nowcast.85-192-42-111.sslip.io:10443`.
Админка `/admin` показывает только выбранные пользователями картинки,
по 60 на страницу. «Удалить» удаляет и запрещает повторную загрузку картинки;
«Бан» дополнительно блокирует все записанные адреса загрузчиков этой картинки.
Выбранные вручную картинки хранятся 6 часов с последней загрузки. Клиент
продлевает загрузку через 4 ч 48 мин, пока картинка нужна.

## Обычные обложки

`Hosts.Upload` / `upload`, а также загрузка выбранных вручную картинок сначала
пробуют Cloudflare. Сетевая ошибка, тайм-аут, временный отказ запускают прямую
загрузку в VPS и общую паузу Cloudflare ровно на 30 минут. В этот период все
новые загрузки сразу идут в VPS. После срока следующая загрузка снова пробует
Cloudflare. Это не фоновый таймер и не лишняя загрузка каждые 30 минут.
Посторонние хостинги не используются. Срок обложки 1 час; продление на 80%
срока (48 минут). Выбранные вручную картинки сохраняют срок 6 часов.
Прямые CDN и поиск iTunes работают как раньше. В админку VPS обычные обложки
не попадают. Одинаковые байты одной обложки хранятся один раз. Если тот же файл
выбран человеком вручную, применяется kind=own и более длинный срок.

## Установка и эксплуатация

Ubuntu 24.04: пакеты nginx, certbot, python3-pil. Скопировать эту папку
в `/opt/nowcast-covers`, запустить `sh provision.sh` от root. Нужны доступные
извне порты 80 и 10443; VPN на 443 не меняется. Скрипт предназначен для этого
сервера: перед установкой на другом нужно проверить занятые порты и nginx.

Служба `nowcast-covers` работает отдельным системным пользователем.
База: `/var/lib/nowcast-covers/covers.db`. Настройки и секреты:
`/etc/nowcast-covers/service.env` (root, режим 600). Ключ входа:
`/etc/nowcast-covers/admin-access.txt`. Не добавлять их в git.
После замены кода: `systemctl restart nowcast-covers`.
Certbot продлевает сертификат по таймеру и перезагружает nginx.

Форматы JPEG/PNG до 256 КиБ с проверкой декодирования, максимум 16 Мп.
Файлы хранятся как SQLite BLOB, общий лимит 5 ГиБ. Срок проверяется при выдаче,
очистка раз в минуту. Лимит 120 успешных загрузок в час на HMAC IP проверяется
атомарно. Реальные адреса не сохраняются в базе, клиентские proxy-заголовки
игнорируются. Блокировки переживают удаление файлов. Кеширование новых
выдач отключено; копии, уже сохранённые самим Discord, отозвать нельзя.

## Worker Cloudflare

`server/worker.js` нужно публиковать отдельно через Edit code → Deploy.
Секрет `BRIDGE_KEY` должен совпадать с одноимённым параметром VPS; ключ админки
для этого не подходит. Привязку существующей D1 оставить с именем `DB`.
Новые загрузки и выдача проксируются из VPS без чтения или записи D1.

Для порта 10443 нужна compatibility date от 2024-09-02 либо флаг
`allow_custom_ports` (и не должен быть включён `ignore_custom_ports`).
Иначе Worker может обращаться на 443, где работает VPN, вместо 10443.
См. https://developers.cloudflare.com/workers/configuration/compatibility-flags/#allow-specifying-a-custom-port-when-making-a-subrequest-with-the-fetch-api
Это нужно проверить в кабинете, а не считать автоматически применённым после
замены JS. При текущей диагностике опубликованный Worker отвечает 503 и запрос
не доходит в сервис VPS; первопричина настройки пока не подтверждена.

Для совместимости со старыми клиентами Worker принимает оба вида картинок и
возвращает собственные `/id.png`, проксируя их из VPS. Новые клиенты используют
VPS напрямую. Недоступность D1 не мешает новым картинкам; D1 нужна только для
старых ссылок, отсутствующих на VPS. Общая модерация применяется в VPS.
`/admin` перенаправляет в админку VPS. VPS является единым хранилищем: его отказ
затронет и Worker. Для правильного продления ссылок нужен новый клиент.

## Проверки

- `python3 -m unittest -v test_app` из server/vps: оба срока, лимиты, запреты,
  фильтр админки.
- `node --test server/worker.test.mjs`: оба вида картинок при исчерпанной D1,
  блокировки и обработка ошибок.
- `python3 /opt/nowcast-covers/verify_https.py` от root: публичный HTTPS,
  вход, CSRF, загрузка, удаление и бан. Только синтетические картинки и
  зарезервированный тестовый адрес; созданные записи убираются.
- `python3 /opt/nowcast-covers/verify_cloudflare.py` от root: публикация
  Worker, загрузка выбранной картинки, её появление в галерее, удаление и
  запрет повторной загрузки через оба входа. Использует синтетическую картинку.
- Windows `tests/run.ps1`, Linux `go vet ./...` и
  `LANG=C.UTF-8 dbus-run-session -- go test -race -count=1 ./...`.

Для копии работающей SQLite использовать `sqlite3.Connection.backup`,
не копировать только .db при работающем WAL. Секреты сохранять отдельно;
при восстановлении сохранить IP_SALT для совпадения старых банов.
