# discord-nowcast

## Актуальная загрузка картинок (29.10.2026)

- Итоговое решение автора: обложки плеера хранятся на VPS 1 час после последней
  загрузки, выбранные вручную картинки — 6 часов. Только выбранные вручную
  картинки показываются в /admin. Идея «вообще не принимать обложки» отменена.
- Итоговое переключение: Cloudflare первым, VPS вторым при временной ошибке,
  сетевой ошибке или тайм-ауте. После ошибки Cloudflare пропускается ровно
  30 минут; следующий запрос после срока снова пробует его первым. Общее
  состояние для обложек и своих картинок. VPS во время паузы доступен всегда.
  Посторонние хостинги удалены. 403 Banned, 451, 400/413/415 не обходятся
  резервом; инфраструктурные 403 Cloudflare (например 1010) допускают резерв.
- Кеш продлевает ссылки на 80% срока: 48 мин для обложек, 4 ч 48 мин для своих.
  Проверено отдельными тестами Windows и Linux. Срок выдачи проверяется
  непосредственно на сервере; очистка устаревших файлов раз в минуту.
- VPS: https://nowcast.85-192-42-111.sslip.io:10443, server/vps,
  nginx + Python/Pillow + SQLite, systemd nowcast-covers, Certbot автопродление.
  VPN на порту 443 не менялся. В /admin только kind=own, обычные обложки скрыты.
- Секреты в /etc/nowcast-covers/service.env и локальных закрытых файлах;
  в git и заметки не записывать. У админки отдельный ключ от BRIDGE_KEY.
- Worker server/worker.js — шлюз в VPS без D1 для новых загрузок. Старые ссылки
  D1 могут временно не работать из-за суточного лимита. Публикация Worker
  отдельно через Edit code → Deploy. Новые клиенты при ошибке Worker работают с VPS,
  не зависят от доступности D1. После публикации Worker старые
  клиенты также передают новые картинки на VPS; для верных сроков нужен новый клиент.
- DiscordInvite: https://discord.gg/SsANGaMr3M. Windows-тесты используют
  временную папку вместо настоящей fallback-picture.

Показывает в статусе Discord («Слушает …», activity type 2) трек, который играет в любом приложении Windows. Один `discord-nowcast.exe` со значком в трее. Родственный проект: `playsin333/claude-code-player`, оттуда взято чтение медиасессий.

## Как устроено (src/)

- `Program.cs`: версия (`Version`, из неё же `AssemblyInfo.cs` — информация о версии в exe, чтобы антивирусы меньше ругались), один экземпляр (мьютекс `Local\discord-nowcast`, брошенный забирается; после обновления ждём старую копию до 15 с).
- `Engine.cs`: отдельный STA-поток (`Media.Open` при ошибке повторяется каждые 30 с; 0x80040154 «Класс не зарегистрирован» = урезанная сборка Windows без SMTC, у значка `Text.MediaRemoved`; 0x80070422 «служба отключена» — `Text.MediaServiceOff`), дважды в секунду `Media.Read` → `Pick` → `Activity.Build` → `Discord.SetActivity`. У каждого сервиса своё приложение Discord (`ClientId` в правилах `Sources.cs`, `Settings.ClientIdFor`; свой `clientId` в настройках перекрывает все): другой источник → закрыть канал (это убирает статус) и подключиться с другим ID. Отправка только при изменении и не чаще раза в 4 с (лимит Discord 5/20 с). Начало трека пересчитывается только при новом отчёте приложения (`StartFor`): Яндекс Музыка держит одну позицию во время игры, раньше это давало «перемотку» и отправку каждые 4 с (что статус не видели друзья, оказалось из-за кнопки на music.yandex.ru, см. «Известные ограничения»). Перемотка — не чаще раза в 30 с. Без длины, но с позицией (`Position` > 0 или `UpdatedAt`) начало тоже считается, в `timestamps` только `start` (Telegram: с середины не 0:00, повтор = перемотка к 0); без длины и позиции — null, время считает сам Discord. Сообщает ли Telegram позицию, не проверено: диагностика показывает позицию и время обновления у каждой сессии. Одинаковая ошибка тика пишется в лог один раз. Менеджер медиасессий после ошибки запрашивается заново (`Media.Read`). Перечитывает `config.json` по FileSystemWatcher.
- `WinRT.cs`, `Media.cs`: медиасессии через рефлексию по типам `..., ContentType=WindowsRuntime`, потому что встроенный csc не читает Windows.winmd (его нет без Windows SDK). Ожидание операций через `WindowsRuntimeSystemExtensions.AsTask`, поток обложки через `AsStreamForRead`, оба вызываются рефлексией.
- `Sources.cs`: имя источника (`names` из настроек → имя из меню «Пуск» через Shell.Application для `_crx_` и `!` → правила) и ссылка поиска для кнопки. Для браузеров сайт ищется по заголовкам окон (`WindowTitles.cs`): окно, где есть название трека или исполнитель, их вырезаем и ищем сервис в остатке; найденный сайт `Media` запоминает на трек, ненайденный ищет снова не чаще раза в 5 с. Имя из меню «Пуск» у известного сервиса заменяется на имя правила («SoundCloud - Music & Audio» → «SoundCloud»). Веб-плеер Spotify — по заголовку «Title • Artist». Firefox: AUMID — хеш папки установки, правило `firefox|^[0-9a-f]{16}$` (любая папка и форки Zen/Floorp/LibreWolf). YouTube и Twitch — `IsVideo`, тип 3 «Смотрит»; трек YouTube с канала «- Topic» или «…VEVO» `Media.Repair` переводит в «Слушает» (копия `SourceInfo` без `IsVideo`, кэш сайтов не трогается). Логотип источника в углу обложки (small_image) пробовали в 1.1.0 и убрали по решению автора: Discord показывал вместо него «?».
- `Covers.cs` (переделан в 1.4.13 по патчу r1nn; загрузка — `Hosts.cs`, обработка картинки — `CoverImage.cs`): сначала картинка из медиасессии — та же, что в плашке громкости, поэтому своя обложка в Телеграме и т.п. видна. Ищется на каждом тике (`Engine` зовёт `Covers.Find` до лимита 4 с), готовая будит движок (`Covers.Ready`). Картинка прошлого трека от того же приложения (`IsStale`, отпечаток FNV; треки одного альбома не считаются) перечитывается до 4 раз. `Prepare`: у Spotify всегда отрезается прозрачная полоса с лого (галочку `logoUnderCover` из патча автор убрал), уменьшение до 300 px, без прозрачности — JPEG 88. Хостинги: свой сервер (Cloudflare Worker `server/worker.js`, `Hosts.Own`, D1, 14 дней, имя файла — SHA-1 картинки) → uguu.se (3 ч) → litterbox (с октября 2026 «412 No file!», у автора 500); x0.at убран 28.10.2026: «403 File type not allowed» на любую картинку, порядок по скорости; упавший пропускается на 1/5/15/30 мин, если упали все — пробуется один, ближайший (`Hosts.Order`); если хостинг молчит 1,5 с, параллельно стартует следующий (`Hedge`). Запись кэша `Covers.Entry`: ссылка, `FromITunes`, `Renew` (80% срока хостинга — загрузить заново) и `Gone` (срок − 10 мин); загрузки ещё и по отпечатку картинки (`byPrint`, альбом — одна загрузка). Повторы без потолка, пока трек текущий: 2, 4 … 60 с (`failures`/`retryAt`), вернувшийся трек получает попытки заново; ошибка iTunes — не ответ (`searched` только после ответа), 403/429 — пауза iTunes 10 мин. В режиме `player` обложка iTunes временная: картинка плеера спрашивается каждые 5 с и заменяет её. Смена `coverSource`/`coverSearch` сбрасывает кэш (`Covers.Reset`), простое «Settings reloaded» — нет. `Engine` хранит `sentImage` (отправленную картинку) и досылает статус, когда `Activity.Image` даёт другую. Подмены для тестов: `Covers.Now/ReadPicture/Upload/LookUp`. iTunes (один ответ на трек, RU и US на русской Windows, только при совпадении исполнителя и названия, видео пропускаются) — если плеер не отдал картинку за 5 взглядов или её не принял ни один хостинг (`orITunes`; `coverSearch` false отключает). Настройка `coverSource` (1.4.14, список в окне вместо галочек): `player` (по умолчанию, как выше), `itunes` (сначала один поиск iTunes, иначе картинка из плеера через тот же путь; для тех, у кого не работают хостинги), `none`; старое `"covers": false` читается как `none`, `Settings.Covers` — вычисляемое. Статус обложку не ждёт: уходит сразу, обложка досылается через `coverCame` (ожидание до 30 с из патча не взято по решению автора: главное — мгновенный статус). Multipart собирается вручную и с User-Agent: MultipartFormDataContent пишет boundary в кавычках и `filename*`, PHP-хостинги не видят файл, а WAF без User-Agent отвечает 500. Нет обложки → нет `assets`, Discord показывает иконку приложения (small_image без large_image не показывается).
- `Activity.cs`: строки (`inList` `source`, если приложение Discord названо по сервису: details — трек, state — исполнитель, `status_display_type` 0, источник в заголовке; иначе «Исполнитель — Трек» / источник; `large_text` в новой карточке Discord — третья строка, там только альбом, `hideAlbum` убирает), `status_display_type`, обложка, полоска, кнопка «Слушать на …» (поиск в том же сервисе, иначе YouTube; ссылка не длиннее 512, иначе Discord отклоняет весь статус, кириллица в ней ×6). Обрезка строк не режет суррогатные пары.
- `Discord.cs`: `\\.\pipe\discord-ipc-N`, кадр op/длина/JSON, ping→pong. `IsAlive` через PeekNamedPipe: иначе перезапуск Discord не виден, пока не сменится трек. Discord ищется каждые 3 с только среди существующих каналов (список через `FindFirstFile`: `Directory.GetFiles` на `\\.\pipe\` падает на чужом канале с недопустимым в путях символом); через 10 с после подключения статус уходит повторно (`resendAt`, повтор в логе — норма). Не нашёл → `Discord not found: …` в лог один раз на причину; `UnauthorizedAccessException` → `IsDenied`, у значка «Нет доступа к Discord: админ или антивирус».
- `Theme.cs`: тёмные цвета Discord, рендерер меню трея (`ToolStripManager.Renderer`), свой `Theme.CheckBox` (системный остаётся белым), тёмный заголовок окна через DWM.
- `TrayApp.cs`: NotifyIcon и меню (в т.ч. «Источники в статусе»); `SettingsForm.cs`: окно настроек (список источников общий с меню — `Settings.SourceChoices`; открыть ссылку/файл — `Program.Open`), каждое изменение сразу пишется в config.json (Settings.Save) и движок перечитывает его; `Startup.cs`: новая установка = exe запущен из нового места (маркер `installed-at` с путём) → HKCU Run и ярлык на рабочем столе; потом выбор пользователя не трогаем (удаление 1.0.x с остановкой процессов powershell убрано в 1.3.0: на него срабатывали антивирусы); `Updater.cs`: GitHub releases/latest, замена exe через переименование в `.old`.
- Свой статус (`OwnForm.cs`, пункт трея «Свой статус…»): вместо трека «Слушает/Смотрит nowcast» (тип 2/3, имя в заголовке) или «Играет в» (тип 0: Discord ставит имя жирным под заголовок, не поднять) на выбор `ownType` (`Activity.Own`: details — строка 1, state — `ownLine2`, если не пустая, `timestamps.start` = момент включения − `ownMinutes`, клик по картинке/названию — `Program.DiscordInvite`, без кнопки). Настройки `own`/`ownType`/`ownTitle`/`ownLine2`/`ownMinutes` (до 100 ч), показывается при названии от 2 символов (`Settings.ShowsOwn`). Приложение Discord `Settings.OwnClientId` (свой `clientId` перекрывает). Картинка: при выборе `CoverImage.FromFile` (≤300 px, JPEG или PNG с прозрачностью) → `%APPDATA%\discord-nowcast\own-picture`; загрузка и обновление ссылки — `Covers.FindFile` (файл узнаётся по времени и размеру), только на свой сервер (`Hosts.UploadOwn`, `?kind=own`, хранится 2 дня, с хешем IP). Модерация: строки со ссылками (известные зоны), казино и 18+ не показываются (`Settings.IsClean`, красная надпись в окне); в воркере `/admin?key=ADMIN_KEY` (секрет в Cloudflare) — последние картинки своих статусов, «Удалить» (хеш в `blocked`, такую больше не примет, 451) и «+ бан» (хеш IP в `banned`, 403). Воркер проверяется локально через `node:sqlite` вместо D1. `Engine.Own` шлёт при изменении названия/времени/картинки, лимит 4 с общий.
- Картинка для треков без обложки (после 1.5.0): «Картинка, если у трека нет обложки» в окне настроек (`PicturePicker` — общий с окном своего статуса: превью, «Выбрать…», «Убрать») → `%APPDATA%\discord-nowcast\fallback-picture` (`Settings.FallbackPicturePath`). `Activity.Image`: обложка → эта картинка → ссылка `image`; загрузка как у своего статуса (`Covers.FindFile`, теперь состояние на каждый путь, `?kind=own`, модерация). Пока обложка ищется, в статусе эта картинка, потом её сменяет обложка (`coverCame`). `coverSource` `picture` (в списке «Своя картинка на всех треках») — обложки не ищутся, эта картинка на всех треках; `none` («Без обложки и картинки») — никакой картинки, даже ссылки `image`. Подпись над картинкой в окне меняется по выбору, при `none` строка скрыта (`SettingsForm.ShowPictureRow`). На Linux — ключ `fallbackPicture` (путь), по умолчанию `fallback-picture` рядом с config.json.
- Текст песни (после 1.5.2, `Lyrics.cs`, настройка `lyrics`, по умолчанию выкл., галочка в окне): строки с таймингами из lrclib.net (`/api/get` по исполнителю, названию и длине, иначе `/api/search` — ближайший по длине ±3 с; только `syncedLyrics`), раз на трек в фоне, ошибка/503 — повтор 2…60 с, «нет текста» — ответ. Строка момента: `Lyrics.Line` по `now − start`, пауза между строками — «♪». В статусе — `large_text` (вместо альбома), без картинки — `state`; только когда играет, не для видео. `Engine`: `sentLyric`, смена строки — повод отправить (лимит 4 с, быстрые строки пропускаются), такая отправка не пишется в лог. Linux: `lyrics.go`, `buildActivity(…, image, lyric)`.
- `Diagnostics.cs`: «Скопировать диагностику» в меню трея — версия, Windows (реестр CurrentVersion), `Engine.Status`/`DiscordState`, сессии, config.json, последние 40 строк лога; путь профиля заменяется на `%USERPROFILE%` (текст выкладывают публично).
- `Text.cs`: строки по-русски на русской Windows, иначе по-английски. Лог (`%APPDATA%\discord-nowcast\log.txt`) по-английски.

## Linux (linux/, бета с 1.5.0)

- Отдельная программа на Go (модуль `linux/go.mod`, go 1.22, без cgo: один статический файл amd64/arm64), логика перенесена из `src/` по смыслу, имена функций — как у C#-оригиналов (`Covers.Find` → `(*Covers).Find`, `StartFor` → `startFor`). Зависимости: `godbus/dbus`, `fyne.io/systray` (StatusNotifierItem + dbusmenu на чистом Go), `golang.org/x/image` (масштаб, webp).
- `mpris.go`: `org.mpris.MediaPlayer2.*` на сессионной шине (`playerctld` пропускается — он повторяет другой плеер), Stopped не показывается. Позиция: если не изменилась с прошлого раза, `UpdatedAt` — время, когда её впервые увидели (иначе застывшая позиция давала бы «перемотку», как у Яндекс Музыки на Windows). «Текущий» — плеер, у которого последним менялись трек или состояние.
- `sources.go`: правила по тексту «шина + DesktopEntry + Identity» (Chrome на Linux — шина `chromium.instanceN`, отличается DesktopEntry/Identity); сайт в браузере — по хосту `xesam:url`, иначе `mpris:artUrl` (`siteSource`), только сервисы со своим приложением Discord. Вместо заголовков окон Windows.
- `covers.go`: как `Covers.cs`; `mpris:artUrl` бывает `file://` (Chromium кладёт в /tmp), `https://`, `data:`. Ссылки с известных открытых CDN (`publicPictures`: i.scdn.co, i.ytimg.com, sndcdn, googleusercontent/ggpht, avatars.yandex.net, mzstatic, jtvnw) уходят в Discord как есть, остальное скачивается и грузится. Хостинги: свой сервер → uguu.se (litterbox не взят). Свой статус: картинка из `ownPicture` (путь, `~/`), пусто — `own-picture` рядом с config.json; `pictureFromFile` уменьшает до 300 px.
- `discord.go`: сокет `discord-ipc-0..9` в `$XDG_RUNTIME_DIR`, `$TMPDIR`, `/run/user/UID`, `/tmp` и их подпапках Flatpak (`app/com.discordapp.Discord`, Canary/PTB, Vesktop) и Snap (`snap.discord`). `IsAlive` — `recv(MSG_PEEK|MSG_DONTWAIT)`.
- `engine.go` — как `Engine.cs` (0,5 с, 4 с, `resendAt`, `startFor`, свой статус); config.json перечитывается по времени и размеру файла. `tray.go`: меню (трек, скрыть на час, свой статус, автозапуск, config.json, лог, диагностика в `diagnostics.txt`, «Вышла версия», сервер, выход); без хоста StatusNotifier работает без значка, значок появится, если хост запустят позже. `autostart.go`: `~/.config/autostart/discord-nowcast.desktop` при запуске из нового места (маркер `installed-at`, путь AppImage — `$APPIMAGE`), запуск из `/tmp` не считается. Самообновления нет, только пункт меню со ссылкой на релиз.
- Папка `~/.config/discord-nowcast` (config.json, log.txt, lock — flock, один экземпляр). Язык — по `LC_ALL`/`LC_MESSAGES`/`LANG`. `discord-nowcast --diagnostics` печатает диагностику без запуска, `--no-tray` — без значка.
- Тесты `linux/*_test.go`: логика без сети, обложки с подменами (`now`, `readPicture`, `upload`, `lookUp`), фейковый Discord на сокете, фейковый MPRIS-плеер и полный путь плеер → движок → Discord (последние два только под `dbus-run-session`, без шины пропускаются). Тесты ждут английских строк: `LANG=C.UTF-8`.
- Упаковка `linux/packaging/package.sh [версия]` → `dist/`: `discord-nowcast-linux-{amd64,arm64}`, `discord-nowcast_{amd64,arm64}.deb`, `discord-nowcast.{x86_64,aarch64}.rpm` (nfpm, `nfpm.yaml`), `discord-nowcast-x86_64.AppImage` (appimagetool 1.9.0 скачивается; `NO_APPIMAGE=1` пропускает — из контейнера Claude запуск скачанного appimagetool запрещён, AppImage проверяется только в CI), `PKGBUILD` для `discord-nowcast-bin` с sha256 (шаблон `aur/PKGBUILD.in`; .desktop, иконка и LICENSE берутся с raw.githubusercontent по тегу). Имена ассетов без версии — ради ссылок `releases/latest/download/…` в README.

## Важно

- Код на C# 5: `build.ps1` собирает встроенным `Framework64\v4.0.30319\csc.exe`. Нельзя `$""`, `?.`, `nameof`, `=>`-члены, инициализаторы автосвойств, `out var`.
- Пути у сессии Claude длинные: `git clone -c core.longpaths=true`; PowerShell 5.1 не запускает `-File` по длинному абсолютному пути (относительный из текущей папки работает).
- Тестовый запуск из временной папки: заранее создать `%APPDATA%\discord-nowcast\config.json`, иначе первый запуск пропишет автозапуск на временный путь.
- Иконка `assets/icon.ico`: маленькие размеры — классические DIB, не PNG, иначе System.Drawing.Icon и трей рисуют мусор. Сделана из картинки ворона автора.
- Основной язык проекта русский: README.md на русском, README.en.md на английском (менять оба), CHANGELOG.md и заметки релизов на русском. Код, комментарии и лог — по-английски.
- Тесты: `tests/Tests.cs` (свой `Main`, без фреймворков: раскладка строк, кнопка, длинные названия, `Media.Repair`, `StartFor`, обрезка обложки, значения по умолчанию), на Windows `tests\run.ps1`. `.github/workflows/check.yml` на каждый пуш собирает exe и гоняет тесты, вторая задача (ubuntu) — gofmt, vet, `go test -race` под `dbus-run-session` и сборка Linux-версии (без релиза). Без Windows: `mcs -langversion:5 -main:Nowcast.Tests src/*.cs tests/*.cs` (+ `-r:` System.Drawing, System.Windows.Forms, System.Net.Http, System.Web.Extensions), `tests/mono-stubs.cs` — заглушки WinRT только для mono; окно можно снять под `xvfb-run`. Шаблоны issues двуязычные, вопросы уводятся в Discussions.

## Релизы

- Поднять `Version` в `src/Program.cs` и добавить `## X.Y.Z` в `CHANGELOG.md` (оттуда заметки релиза). При пуше в `main` `.github/workflows/release.yml`: задача `version` (есть ли уже релиз), затем `windows` (exe) и `linux` (`package.sh`) параллельно, артефакты собирает `release` и создаёт `vX.Y.Z` со всеми файлами. Версия Linux-программы берётся из той же `Version` (`-ldflags -X main.version`). После релиза PKGBUILD из ассетов автор заливает в AUR сам. README ссылается на `releases/latest/download/discord-nowcast.exe`, а программа обновляется из этого же ассета.

## Известные ограничения

- Пусто в «Что видит Windows», нет плашки у громкости, в логе 0x80040154 — урезанная сборка Windows. Не чинится программой; DISM /RestoreHealth с /Source из ISO той же версии или обычная Windows.
- «Media sessions unavailable: … 0x80070422» — в Windows отключена служба (обычно оптимизатор). Какая именно, пока не выяснено: смотреть журнал «Система», ошибку Service Control Manager.
- «Discord not found: no discord-ipc pipe» — Discord закрыт или браузерный.
- «Discord not found: discord-ipc-0: Отказано в доступе» — Discord от администратора/другого пользователя или антивирус (Avast) запускает exe в песочнице: исключение в антивирусе или запуск nowcast от администратора.
- Кнопка со ссылкой на `music.yandex.ru`: Discord принимает статус, но друзьям его не показывает (проверено у пользователя 24.10.2026: без кнопки видно, хотя `details_url` с той же ссылкой оставался; SoundCloud и Telegram с кнопкой видно). Поэтому у правила Яндекс Музыки `Search` = null, кнопка ищет на YouTube.
- Яндекс Браузер не передаёт трек в SMTC (ВК Музыка и SoundCloud у двух пользователей, 24.10.2026): «Что видит Windows» пусто, в Edge работает; флаг Hardware Media Key Handling и `--enable-features=MediaSessionService` не помогают, трека нет и в заголовке окна («Яндекс — Яндекс Браузер»). Не чинится программой, в README «Ограничения».
- Яндекс Музыка: приложение (разобран 5.124.1) отдаёт трек только через `navigator.mediaSession` → SMTC; заголовок окна — название страницы, не трек. В обход Windows только Ynison по OAuth-токену — не делаем.
