# discord-nowcast

Показывает в статусе Discord («Слушает …», activity type 2) трек, который играет в любом приложении Windows. Один `discord-nowcast.exe` со значком в трее. Родственный проект: `playsin333/claude-code-player`, оттуда взято чтение медиасессий.

## Как устроено (src/)

- `Program.cs`: версия (`Version`, из неё же `AssemblyInfo.cs` — информация о версии в exe, чтобы антивирусы меньше ругались), один экземпляр (мьютекс `Local\discord-nowcast`, брошенный забирается; после обновления ждём старую копию до 15 с).
- `Engine.cs`: отдельный STA-поток (`Media.Open` при ошибке повторяется каждые 30 с; 0x80040154 «Класс не зарегистрирован» = урезанная сборка Windows без SMTC, у значка `Text.MediaRemoved`; 0x80070422 «служба отключена» — `Text.MediaServiceOff`), дважды в секунду `Media.Read` → `Pick` → `Activity.Build` → `Discord.SetActivity`. У каждого сервиса своё приложение Discord (`ClientId` в правилах `Sources.cs`, `Settings.ClientIdFor`; свой `clientId` в настройках перекрывает все): другой источник → закрыть канал (это убирает статус) и подключиться с другим ID. Отправка только при изменении и не чаще раза в 4 с (лимит Discord 5/20 с). Начало трека пересчитывается только при новом отчёте приложения (`StartFor`): Яндекс Музыка держит одну позицию во время игры, раньше это давало «перемотку» и отправку каждые 4 с (что статус не видели друзья, оказалось из-за кнопки на music.yandex.ru, см. «Известные ограничения»). Перемотка — не чаще раза в 30 с. Одинаковая ошибка тика пишется в лог один раз. Менеджер медиасессий после ошибки запрашивается заново (`Media.Read`). Перечитывает `config.json` по FileSystemWatcher.
- `WinRT.cs`, `Media.cs`: медиасессии через рефлексию по типам `..., ContentType=WindowsRuntime`, потому что встроенный csc не читает Windows.winmd (его нет без Windows SDK). Ожидание операций через `WindowsRuntimeSystemExtensions.AsTask`, поток обложки через `AsStreamForRead`, оба вызываются рефлексией.
- `Sources.cs`: имя источника (`names` из настроек → имя из меню «Пуск» через Shell.Application для `_crx_` и `!` → правила) и ссылка поиска для кнопки. Для браузеров сайт ищется по заголовкам окон (`WindowTitles.cs`): окно, где есть название трека или исполнитель, их вырезаем и ищем сервис в остатке; найденный сайт `Media` запоминает на трек, ненайденный ищет снова не чаще раза в 5 с. Имя из меню «Пуск» у известного сервиса заменяется на имя правила («SoundCloud - Music & Audio» → «SoundCloud»). Веб-плеер Spotify — по заголовку «Title • Artist». Firefox: AUMID — хеш папки установки, правило `firefox|^[0-9a-f]{16}$` (любая папка и форки Zen/Floorp/LibreWolf). YouTube и Twitch — `IsVideo`, тип 3 «Смотрит»; трек YouTube с канала «- Topic» или «…VEVO» `Media.Repair` переводит в «Слушает» (копия `SourceInfo` без `IsVideo`, кэш сайтов не трогается). Логотип источника в углу обложки (small_image) пробовали в 1.1.0 и убрали по решению автора: Discord показывал вместо него «?».
- `Covers.cs` (переделан в 1.4.13 по патчу r1nn; загрузка — `Hosts.cs`, обработка картинки — `CoverImage.cs`): сначала картинка из медиасессии — та же, что в плашке громкости, поэтому своя обложка в Телеграме и т.п. видна. Ищется на каждом тике (`Engine` зовёт `Covers.Find` до лимита 4 с), готовая будит движок (`Covers.Ready`). Картинка прошлого трека от того же приложения (`IsStale`, отпечаток FNV; треки одного альбома не считаются) перечитывается до 4 раз. `Prepare`: у Spotify всегда отрезается прозрачная полоса с лого (галочку `logoUnderCover` из патча автор убрал), уменьшение до 300 px, без прозрачности — JPEG 88. Хостинги uguu.se → x0.at → litterbox (с октября 2026 «412 No file!»), порядок по скорости, упавший на 10 минут в конец; если хостинг молчит 1,5 с, параллельно стартует следующий (`Hedge`). iTunes (`coverSearch`, один запрос на трек, RU и US на русской Windows, только при совпадении исполнителя и названия, видео пропускаются) — если плеер не отдал картинку за 5 попыток или её не принял ни один хостинг (`orITunes`). Статус обложку не ждёт: уходит сразу, обложка досылается через `coverCame` (ожидание до 30 с из патча не взято по решению автора: главное — мгновенный статус). Multipart собирается вручную и с User-Agent: MultipartFormDataContent пишет boundary в кавычках и `filename*`, PHP-хостинги не видят файл, а WAF без User-Agent отвечает 500. Нет обложки → нет `assets`, Discord показывает иконку приложения (small_image без large_image не показывается).
- `Activity.cs`: строки (`inList` `source`, если приложение Discord названо по сервису: details — трек, state — исполнитель, `status_display_type` 0, источник в заголовке; иначе «Исполнитель — Трек» / источник; `large_text` в новой карточке Discord — третья строка, там только альбом, `hideAlbum` убирает), `status_display_type`, обложка, полоска, кнопка «Слушать на …» (поиск в том же сервисе, иначе YouTube; ссылка не длиннее 512, иначе Discord отклоняет весь статус, кириллица в ней ×6). Обрезка строк не режет суррогатные пары.
- `Discord.cs`: `\\.\pipe\discord-ipc-N`, кадр op/длина/JSON, ping→pong. `IsAlive` через PeekNamedPipe: иначе перезапуск Discord не виден, пока не сменится трек. Discord ищется каждые 3 с только среди существующих каналов (список через `FindFirstFile`: `Directory.GetFiles` на `\\.\pipe\` падает на чужом канале с недопустимым в путях символом); через 10 с после подключения статус уходит повторно (`resendAt`, повтор в логе — норма). Не нашёл → `Discord not found: …` в лог один раз на причину; `UnauthorizedAccessException` → `IsDenied`, у значка «Нет доступа к Discord: админ или антивирус».
- `Theme.cs`: тёмные цвета Discord, рендерер меню трея (`ToolStripManager.Renderer`), свой `Theme.CheckBox` (системный остаётся белым), тёмный заголовок окна через DWM.
- `TrayApp.cs`: NotifyIcon и меню (в т.ч. «Источники в статусе»); `SettingsForm.cs`: окно настроек (список источников общий с меню — `Settings.SourceChoices`; открыть ссылку/файл — `Program.Open`), каждое изменение сразу пишется в config.json (Settings.Save) и движок перечитывает его; `Startup.cs`: новая установка = exe запущен из нового места (маркер `installed-at` с путём) → HKCU Run и ярлык на рабочем столе; потом выбор пользователя не трогаем (удаление 1.0.x с остановкой процессов powershell убрано в 1.3.0: на него срабатывали антивирусы); `Updater.cs`: GitHub releases/latest, замена exe через переименование в `.old`.
- `Diagnostics.cs`: «Скопировать диагностику» в меню трея — версия, Windows (реестр CurrentVersion), `Engine.Status`/`DiscordState`, сессии, config.json, последние 40 строк лога; путь профиля заменяется на `%USERPROFILE%` (текст выкладывают публично).
- `Text.cs`: строки по-русски на русской Windows, иначе по-английски. Лог (`%APPDATA%\discord-nowcast\log.txt`) по-английски.

## Важно

- Код на C# 5: `build.ps1` собирает встроенным `Framework64\v4.0.30319\csc.exe`. Нельзя `$""`, `?.`, `nameof`, `=>`-члены, инициализаторы автосвойств, `out var`.
- Пути у сессии Claude длинные: `git clone -c core.longpaths=true`; PowerShell 5.1 не запускает `-File` по длинному абсолютному пути (относительный из текущей папки работает).
- Тестовый запуск из временной папки: заранее создать `%APPDATA%\discord-nowcast\config.json`, иначе первый запуск пропишет автозапуск на временный путь.
- Иконка `assets/icon.ico`: маленькие размеры — классические DIB, не PNG, иначе System.Drawing.Icon и трей рисуют мусор. Сделана из картинки ворона автора.
- Основной язык проекта русский: README.md на русском, README.en.md на английском (менять оба), CHANGELOG.md и заметки релизов на русском. Код, комментарии и лог — по-английски.
- Тесты: `tests/Tests.cs` (свой `Main`, без фреймворков: раскладка строк, кнопка, длинные названия, `Media.Repair`, `StartFor`, обрезка обложки, значения по умолчанию), на Windows `tests\run.ps1`. `.github/workflows/check.yml` на каждый пуш собирает exe и гоняет тесты (без релиза). Без Windows: `mcs -langversion:5 -main:Nowcast.Tests src/*.cs tests/*.cs` (+ `-r:` System.Drawing, System.Windows.Forms, System.Net.Http, System.Web.Extensions), `tests/mono-stubs.cs` — заглушки WinRT только для mono; окно можно снять под `xvfb-run`. Шаблоны issues двуязычные, вопросы уводятся в Discussions.

## Релизы

- Поднять `Version` в `src/Program.cs` и добавить `## X.Y.Z` в `CHANGELOG.md` (оттуда заметки релиза). При пуше в `main` `.github/workflows/release.yml` на windows-latest собирает exe и создаёт релиз `vX.Y.Z` с `discord-nowcast.exe`. README ссылается на `releases/latest/download/discord-nowcast.exe`, а программа обновляется из этого же ассета.

## Проверка

- Не проверено на Windows: клик по обложке/названию (`large_url`/`details_url`, при отказе Discord `Activity.UseLinks` выключается), SoundCloud по заголовку «▶ Title by Artist», переключение приложений между сервисами, x0.at из России.
- Хостинги обложек (проверка 23.10.2026 из контейнера): работают uguu.se и x0.at (x0.at у пользователя из России ответил «403 Your IP is banned from uploading»); litterbox и catbox — 412; qu.ax отдаёт страницу-просмотрщик, не картинку; pomf2.lain.la 403; tmpfiles.org и 0x0.st из контейнера недоступны; freeimage.host только с чужим демо-ключом — не брать.
- Без Windows: `apt-get install mono-devel`, `mcs -langversion:5` с заглушками, харнесс со своим `Main` (`-main:`), окно снимать `import -window root` под `xvfb-run -s "-screen 0 700x800x24"` (`DrawToBitmap` в mono рисует пустой фон). iTunes из контейнера быстро даёт 403 (лимит на IP), у пользователей это не проблема.

## Известные ограничения

- Пусто в «Что видит Windows», нет плашки у громкости, в логе 0x80040154 — урезанная сборка Windows. Не чинится программой; DISM /RestoreHealth с /Source из ISO той же версии или обычная Windows.
- «Media sessions unavailable: … 0x80070422» — в Windows отключена служба (обычно оптимизатор). Какая именно, пока не выяснено: смотреть журнал «Система», ошибку Service Control Manager.
- «Discord not found: no discord-ipc pipe» — Discord закрыт или браузерный.
- «Discord not found: discord-ipc-0: Отказано в доступе» — Discord от администратора/другого пользователя или антивирус (Avast) запускает exe в песочнице: исключение в антивирусе или запуск nowcast от администратора.
- Кнопка со ссылкой на `music.yandex.ru`: Discord принимает статус, но друзьям его не показывает (проверено у пользователя 24.10.2026: без кнопки видно, хотя `details_url` с той же ссылкой оставался; SoundCloud и Telegram с кнопкой видно). Поэтому у правила Яндекс Музыки `Search` = null, кнопка ищет на YouTube.
- Яндекс Музыка: приложение (разобран 5.124.1) отдаёт трек только через `navigator.mediaSession` → SMTC; заголовок окна — название страницы, не трек. В обход Windows только Ynison по OAuth-токену — не делаем.
